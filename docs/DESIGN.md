## 1. 확정된 의사결정 (근거 포함)

1. **FSD 프로필 자동 전환(type 167 송신) 삭제.** 원본의 카메라 기능은 FSD Chill/Standard/Hurry 전환 명령을 차량에 보낸다. R1(쓰기 금지)에 정면으로 위배된다. 카메라 **경고(배너+경고음)만 유지**한다. "통과 후 복귀 프로필" 설정 UI도 삭제한다.
2. **Tailwind CDN 제거 → 순수 CSS.** CDN 런타임 JIT는 로딩이 느리고, 오프라인(지하주차장 등)에서 깨지며, 공식적으로 프로덕션 비권장이다. CSS 변수 기반 테마와도 궁합이 좋다.
3. **빌드 도구 없는 바닐라 ES 모듈, 다중 파일.** Web Bluetooth는 어차피 HTTPS(또는 localhost) 호스팅이 필요하므로 단일 파일의 이점이 없다. 나중에 Capacitor로 APK 포장할 때 그대로 `www/`로 쓴다.
4. **PWA(manifest + service worker) 포함.** 홈 화면 설치, 전체화면 실행, 오프라인 실행. APK 전 단계의 "앱처럼 쓰기"를 해결한다.
5. **프로토콜 파싱 로직(176/208)은 원본 비트 연산을 그대로 옮긴다.** 사용자가 "확정 명세"라고 했으므로 수정하지 않는다. 모듈로 분리해 테스트만 붙인다.
6. **기존 기능 유지:** 데모, 0-100 측정, 트립 기록, TPMS/브레이크 온도, HV 팩, HUD 반전, 카메라 DB(가져오기/테스트/초기화), 경고음, EV 사운드 2종(한스짐머 EV, 플래드 워프), 테마 4종.
7. **새 테마는 1개만 추가: "나이트".** 화면 단순화 요구(R7)와 충돌하지 않는 가장 실용적인 테마.

## 3. 읽기 전용 보장 (R1)

`protocol.js`:

```js
// 모듈 프로토콜 요청만 허용. 차량 제어 명령은 존재하지 않는다.
export const ALLOWED_TX_TYPES = Object.freeze({
  INFO: 160,       // 모듈 정보 요청 (HW 버전)
  AUTH: 168,       // 모듈 비밀번호 인증
  TELEMETRY: 176,  // 실시간 텔레메트리 구독 [1]/해제 [0]
  HV_PACK: 208,    // 고전압 팩 정보 요청
});
export function encodePacket(type, payload) // 화이트리스트 외 type이면 Error throw
```

- 패킷 포맷은 원본과 동일: `55 7F type lenHi lenLo payload… sum(type..payload)&0xFF`.
- `ble.js`는 반드시 `encodePacket`을 통해서만 송신한다. `writeValue*` 호출부는 `ble.js` 한 곳에만 존재해야 한다.
- 테스트: 160/168/176/208은 통과, 167 및 그 외 임의 값은 throw.
- 원본 `FSD_PROFILE_CMD`, `sendFsdSpeedProfileCmd`, `setPreferredFsdProfile`, 관련 UI/문구는 모두 제거.

## 4. BLE 연결 및 자동 연결 (R3)

### 4.1 상태 머신
`idle → connecting → connected → (reconnecting) → connected` / 수동 해제 시 `idle`.
UI에는 상태 점 1개 + 짧은 라벨만 표시(§5).

### 4.2 최초 연결
- 사용자 탭 → `requestDevice({ filters:[{services:[SVC]}] })` (원본과 동일 UUID).
- 연결 성공 시 저장: `tsl_last_device_id`, `tsl_last_device_name`.
- 연결 후 시퀀스(원본 유지): +180ms 비밀번호(168) → +150ms 정보(160) → +170ms 텔레메트리 구독(176 [1]) → 1초마다 176 [1] 유지.

### 4.3 앱 실행 시 자동 연결
1. `tsl_autoconnect`(기본 ON)가 켜져 있고 저장된 id가 있으면 시도.
2. `navigator.bluetooth.getDevices` 가 있으면 목록에서 id 일치 기기를 찾는다.
   - 찾으면 `device.gatt.connect()` 시도.
   - 실패하고 `device.watchAdvertisements` 가 있으면 광고 수신 대기 → `advertisementreceived` 시 연결. 대기 중 라벨: "기기 찾는 중".
   - 둘 다 실패하면 10초 간격 재시도(최대 무한, 화면이 보이는 동안만 — `visibilitychange`로 일시정지).
3. `getDevices` 가 없거나 기기를 못 찾으면: 상단에 얇은 배너 "화면을 탭하면 TSL 모듈에 연결합니다". 다음 **아무 곳 첫 탭**(사용자 제스처)에서 `requestDevice` 호출. 이 배너는 한 번 탭하면 사라진다.
4. 데모 모드 실행 중에는 자동 연결하지 않는다.

### 4.4 끊김 시 재연결
- `gattserverdisconnected` 이고 수동 해제가 아니면 재연결: 1s, 2s, 4s, 8s, 이후 15s 간격.
- 토스트는 "연결 끊김 · 재연결 중" 1회만(원본의 중복 토스트 버그 수정: 수동 해제 시 `onDisconnected` 가 두 번 불리는 문제).
- 재연결 시 `characteristicvaluechanged` 리스너 중복 등록 금지.

### 4.5 설정
설정 시트 "연결" 섹션: 자동 연결 ON/OFF, 비밀번호(4자리), "저장된 기기 지우기", 현재 기기명.

## 5. 화면 레이아웃 (R2, R7)

### 5.1 원칙
- 주행 중 메인 화면에는 **운전에 필요한 것만**: 속도, 기어, 방향지시등, 출력/회생 바, 배터리%/주행가능거리, 제한속도, 경고(핸들/카메라).
- 나머지(TPMS, 브레이크 온도, HV 팩, 트립, 온도, ODO, 고도)는 **정보 시트**로 이동.
- 설정(사운드, 테마, 연결, 카메라, 데모, 0-100, 트립 초기화)은 **설정 시트**로 이동.
- 상단 아이콘 버튼 6개 + 하단 독 5개 → **화면 버튼 2개(ⓘ 정보, ⚙ 설정)**. 연결 상태 표시는 탭 시 연결/해제.
- 전체화면: 첫 탭 시 자동 요청(실패해도 조용히 무시). 화면 꺼짐 방지(Wake Lock): 연결됨 또는 데모 중이면 자동 요청, `visibilitychange` 로 복귀 시 재요청. 수동 버튼 제거.
- 터치 타깃 최소 44×44px.

- 화면 하단에서 올라오는 시트, 최대 높이 85dvh, 내부 스크롤. 배경 탭 또는 ✕로 닫기.

- 카메라 경고: 상단 배너 "단속 카메라 320m · 제한 80". FSD 문구 삭제.

- AP 활성: 상태줄 기어 옆에 작은 파란 "AP" 칩(비활성 시 숨김).

## 6. 사운드 엔진 (R4)

### 6.1 문제 진단 (원본)
원본 V8/GT는 고정된 몇 개 발진기의 주파수만 옮긴다. 실제 배기음의 핵심인 **실린더별 폭발 펄스의 불균일성(럼블), 배기관 공명, 부하에 따른 음색 변화, 변속 시 RPM 낙차, 오버런 팝** 이 없어 "신디사이저 윙윙" 소리가 난다.

### 6.2 구조
```
main thread                              AudioWorklet (engine-worklet.js)
rpm-model.js  ──(rpm, throttle 60Hz)──▶  펄스 생성기 → 배기관 웨이브가이드 → 머플러 필터
                                          → 흡기/기계 노이즈 → 소프트 클립 → out
```
- `audioWorklet.addModule('js/audio/engine-worklet.js')`. 파라미터는 `AudioParam`(`rpm`, `throttle`, `gain`)로 전달, 프로필 설정은 `port.postMessage`.
- AudioContext는 사용자 제스처 후에만 시작. 저장된 프로필이 있으면 첫 탭에서 자동 재개.

### 6.3 펄스 생성 (worklet, 샘플 단위)
- 크랭크 각 `θ` (0–720°, 4행정)를 매 샘플 `rpm/60*360/sampleRate` 만큼 전진.
- 프로필별 점화 각도 배열을 지나칠 때마다 해당 실린더 펄스 발생.
- 펄스 = 짧은 지수감쇠 노이즈 버스트(1.5–4ms) + 저역 감쇠 사인 "쿵"(펄스 주파수 대역). 진폭 = `(0.25 + 0.75*throttle) * (1 ± 6% 랜덤)`, 타이밍 지터 ±0.15ms.
- 각 펄스는 실린더가 속한 뱅크(0/1)의 배기관으로 들어간다.

### 6.4 배기관/머플러
- 뱅크별 웨이브가이드: 딜레이 라인(길이 = 관 길이, 2–6ms) + 피드백 0.35–0.6 + 루프 내 1차 로우패스. 두 뱅크 길이를 약간 다르게(비대칭이 럼블을 만든다).
- 머플러: 피킹 필터 2개(프로필별 공명 주파수) + 로우패스(컷오프 = `base + rpm*k1 + throttle*k2`, 1-pole 스무딩).
- 흡기/기계 노이즈: 밴드패스 노이즈, 레벨 ∝ rpm, 중심주파수 ∝ rpm.
- 마스터: `tanh(drive*x)/tanh(drive)`, `drive = 1.2 + 2.5*throttle`.

### 6.5 프로필 (내연기관 2종 + 기존 EV 2종)
| 키 | 이름 | 점화 각(720° 내) / 뱅크 | idle/레드존 | 성격 |
|---|---|---|---|---|
| `v8` | V8 머슬 | 크로스플레인: 각 실린더 90° 간격, 뱅크 배정 `[0,1,0,0,1,0,1,1]`(뱅크별 불균일 간격 → 고유의 두둥두둥) | 750 / 6500 | 저음 강조, 피킹 90Hz·220Hz |

정확한 계수(감쇠, 피드백, 필터 Q)는 구현자가 청취 없이 정할 수 없으므로 **위 범위 내 값으로 시작하고 상수로 한 곳(`PROFILES` 객체)에 모은다.** 튜닝은 사용자 청취 피드백으로 이후 조정.

### 6.6 가상 RPM 모델 (`rpm-model.js`, 순수 함수 + 상태 객체)
```js
export function createRpmModel(profile)  // {idle, redline, gearRatios[6], finalDrive, wheelCircM}
export function stepRpm(model, { speedKmh, pedalPct, dtSec }) // → { rpm, gear, throttle, event }
```
- 바퀴 회전 기반 RPM = `speed/3.6 / wheelCirc * 60 * ratio[gear] * finalDrive`, `max(idle, …)`.
- 자동 변속: 업시프트 RPM = `lerp(0.45, 0.92, pedal/100) * redline`, 다운시프트 RPM = `idle*1.6`(킥다운: 페달 > 85%이고 한 단 낮춰도 레드라인 미만이면 다운).
- 변속 시: 0.12s 동안 throttle 0 (점화 컷), RPM은 새 기어 값으로 시상수 0.08s 로 이동. `event: 'upshift'|'downshift'`.
- 정차(속도<2) 시: idle ± 25rpm 느린 흔들림; 페달 입력 시 공회전 레브(`idle + pedal*0.6*redline`, 시상수 0.15s 상승 / 0.35s 하강).
- 레브 리미터: rpm ≥ redline 이면 worklet에서 펄스를 50ms 주기로 절반 컷.
- 오버런: throttle이 0.6→0.1 미만으로 급감하고 rpm > 0.45*redline 이면 0.4–1.2s 동안 worklet이 랜덤 팝(밴드패스 노이즈 크랙, 확률 기반) 발생.
- RPM 스무딩: 시상수 0.1s (계기 데이터가 거칠어도 소리가 끊기지 않게).
- 업데이트 주기: `requestAnimationFrame` 또는 50ms 타이머로 최신 텔레메트리 값 기반 보간.

### 7.1 플래드 테마 — "실제 플래드 가속" 연출
가정: 사용자가 말한 "플래드모드 주행효과"는 플래드 가속 시 화면에 나오는 **광속(하이퍼스페이스) 빛줄기가 소실점으로부터 뻗어 나오는 연출**이다. (틀리면 사용자 확인 후 수정)

원본의 문제: 강도가 페달·속도만으로 결정되어 정속 고속주행에서도 계속 워프가 나오고, 가속감과 무관하다.

설계:
- **강도 `I` (0–1) = 가속도 기반.** `I = clamp(max(accelG/0.6, totalKw/peakKw*0.8), 0, 1)`, `peakKw` 는 트립 최대출력(최소 200). accelG는 속도 미분값을 EMA(시상수 0.3s) 스무딩. `I` 자체도 상승 시상수 0.15s, 하강 0.8s.
- `I < 0.05`: 별 입자가 아주 느리게 앞으로 흘러가는 정적인 공간(거의 검정).
- `I` 증가 시: 빛줄기 속도·길이 증가(길이 ∝ I²), 중심부 청백색 블룸(라디얼 그라디언트), 가장자리 약한 비네트.
- `I > 0.6` (풀 가속): 빛줄기가 소실점에서 쏟아지는 하이퍼스페이스, 속도 숫자에 청백색 글로우, 화면 전체 미세 진동(±1px, 30Hz 이내) 0.3s.
- 감속/회생(accelG < -0.1): 빛줄기가 감속하며 짧아지고 색이 따뜻한 적색 계열로 잠깐 이동.
- 색: 줄기 85% 흰색~청색(#DDEBFF, #7FB7FF), 15% 적색 포인트(#FF3B5C, 플래드 상징색).
- 소실점: 속도 숫자 중심.
- 성능: 입자 160개, `devicePixelRatio` 최대 2, 테마가 plaid가 아니면 rAF 루프 정지(원본은 항상 돌았음 → 배터리 낭비 수정). `prefers-reduced-motion` 이면 진동 생략.

## 9. 웹 vs APK (R6) — 의견

**결론: 지금은 웹(PWA)으로 계속 개발하고, 자동 연결이 웹에서 기대만큼 안 되면 그 시점에 Capacitor로 APK 포장한다.** 코드를 새로 짤 필요 없이 `app/` 폴더를 그대로 감싼다.

- 웹으로 개발하는 이유: 수정→새로고침 사이클이 빠르고, 데모 모드로 PC에서 UI/사운드를 확인할 수 있다.
- APK가 필요해지는 이유(웹의 한계):
  1. **자동 연결**: Web Bluetooth의 `getDevices()`/`watchAdvertisements()`는 Android Chrome에서 플래그(`chrome://flags/#enable-web-bluetooth-new-permissions-backend`)가 필요할 수 있다. 네이티브는 제한 없음.
  2. 화면 꺼짐/백그라운드 시 연결 유지, BLE 안정성.
  3. iPhone은 Web Bluetooth 자체가 없다(Safari 미지원) → 아이폰 지원이 필요하면 무조건 네이티브.
- 대비: `ble.js` 의 외부 인터페이스(`connect, disconnect, autoConnect, onPacket, onState, send`)를 고정해 두면 APK 전환 시 `@capacitor-community/bluetooth-le` 기반 구현으로 이 파일만 교체하면 된다.
- 이번 범위에서는 Capacitor 작업을 하지 않는다.

4. "첫 탭"은 버튼, 입력, 시트 안쪽을 제외한다(구현대로 확정).
5. 구현자 판단 2~12번(npm test 글롭, 오버런 기준을 페달로, 킥다운 0.92×레드라인, 공회전 레브의 pedal 0~1 해석, 변속 쿨다운 0.35s, 재연결 시 시퀀스 재수행, 나이트 `brightness(0.6)`, 테마 비저장, 팩 갱신 버튼 미포함)은 모두 승인.

리뷰에서 추가된 요구:
6. **사용자 제스처 이벤트는 `click`(capture)으로 처리한다.** 터치에서 `pointerdown`은 사용자 활성화(user activation) 이벤트가 아니므로 `requestDevice`, `requestFullscreen`, `AudioContext.resume`이 휴대폰에서 실패한다. 오디오 컨텍스트가 `suspended`이면 클릭마다 `resume()`을 시도한다. 미리듣기 버튼은 누르는 동안 동작은 유지하되, 컨텍스트 생성/재개가 활성화 이벤트(`click` 또는 `pointerup`/`touchend`)에서도 시도되게 한다.
7. **겹침 금지:** 모든 테마·뷰포트(§10의 4개)에서 속도 숫자(3자리 기준) 영역이 방향지시등, 제한속도 표지, 출력/배터리 정보, 트랙 프레임 내부 요소(SHIFT/PK/THR/REG/LONG-G)와 겹치지 않는다. 방향지시등은 속도 칸 바깥의 고정 폭 열에 둔다. 트랙 테마는 프레임이 속도 숫자를 감싸도록 크기를 잡거나 트랙 테마일 때 속도 글자를 줄인다.
8. **세로 모드 속도 숫자 확대:** 3자리가 들어가는 한도 안에서 화면 폭의 약 70%까지(390px 폭 기준 3자리 숫자 폭 ≥ 250px).
9. 스모크 테스트는 데모에서 속도가 3자리(≥100)가 된 시점에 위 겹침 검사(요소 bounding rect 교차)를 5개 테마 × 4개 뷰포트 모두 수행한다.

6. (리뷰 결정) **핸들 잡기 경고 위치:** 경고는 줄바꿈 없이 한 줄(`nowrap`).

  | `motor` | 일렉트릭 슈퍼카 | 고성능 전기모터 휘닝. 기본음 `f = 180 + speed*9` Hz(최대 2.6kHz) 사인 + 2배음(0.35)·3배음(0.15). 인버터 음: `f*1.5`의 약한 삼각파(0.08). 기어 휘닝: `f*0.5` 사인(0.12). 음량 = `0.05 + 0.95*powerNorm`(powerNorm = clamp(max(pedal/100, kW/peakKw),0,1)), 회생(kW<0) 시 음량 `0.3*regenNorm`, 음높이 그대로. 하이패스 120Hz, 피킹 1.2kHz +4dB Q1. 시상수 0.06s. |
  | `turbine` | 제트 터빈 | 터빈 스풀. 내부 "스풀" 값 s(0–1)가 목표 `max(pedal/100, speed/220*0.6)`를 상승 시상수 0.8s, 하강 1.5s로 따라감(관성). 휘슬: 사인 `600 + s*3400` Hz(0.10)와 `*1.5`(0.05). 공기 흐름: 핑크 노이즈 → 밴드패스(중심 `300 + s*2200`Hz, Q 0.9), 음량 `0.04 + s*0.25`. 저역 럼블: 사인 `45 + s*40` Hz (0.25*s). 리버브는 기존 createSpaceReverb 재사용(wet 0.15). |
- 상태 계산은 순수 함수로 분리: `app/js/audio/ev-params.js` `export function motorParams({speed,pedal,kw,peakKw})`, `export function turbineTarget({speed,pedal})`, `export function stepSpool(s, target, dt)` → 테스트 `tests/ev-params.test.mjs`(속도 증가 시 주파수 단조 증가·상한, 회생 시 음량 감소, 스풀 상승이 하강보다 빠름, 범위 0–1).
- 설정 시트 사운드 버튼: 음소거 / 한스짐머 EV / 플래드 워프 / 일렉트릭 슈퍼카 / 제트 터빈. 저장된 프로필이 `v8`·`gt6`이면 `off`로 바꾼다(마이그레이션).
- 미리듣기·볼륨·경고음은 그대로.

### 14.2 테마
- 삭제: `dial`, `track`, `night` 마크업·CSS·JS·스모크 검사. 저장된 테마가 이 값이면 `minimal`로(현재는 비저장이지만 방어).
- 유지(변경 금지): `minimal`, `plaid`.
- 신규 3종은 **잘림 방지를 구조로 보장**한다: 상태줄과 하단 버튼 줄 사이의 클러스터 영역 전체를 **SVG 한 장**으로 그린다. `viewBox` 고정 + `preserveAspectRatio="xMidYMid meet"` → 어떤 화면비에서도 잘리지 않고 비율 유지(남는 공간은 여백). 클러스터 영역의 가로/세로 비율이 1 이상이면 가로용, 아니면 세로용 SVG를 표시(ResizeObserver).

## 15. v2.1: 업데이트 안정화, 새로고침·종료 버튼

실기기 보고: 배포 후 새 사운드(motor, turbine)·새 테마(arc, twin, hud)가 동작하지 않음. 데스크톱 Chromium 스모크에서는 동작하므로, 원인은 **구버전·신버전 파일 혼재**로 판단한다: GitHub Pages는 `Cache-Control: max-age=600`을 보내고, 서비스워커의 `fetch(req)`·`cache.addAll()`은 브라우저 HTTP 캐시를 그대로 쓴다. 그래서 새 `index.html`(새 버튼)과 옛 `main.js`/`ui.js`(새 키를 모름)가 섞일 수 있다.

### 15.1 캐시 혼재 방지
- `app/js/version.js`: `export const APP_VERSION = '2.1.0';` (배포마다 올림). `sw.js`의 캐시 이름도 `tsl-shell-<버전>`으로 맞춘다(sw.js는 모듈이 아니므로 같은 문자열을 상수로 직접 둔다. 두 값 일치를 단위 테스트로 검사).
- `sw.js`:
  - install: `cache.addAll(SHELL.map(u => new Request(u, { cache: 'reload' })))`
  - fetch(같은 출처 GET): `fetch(req, { cache: 'no-cache' })` (서버 재검증) → 성공 시 캐시 갱신, 실패(오프라인) 시 캐시.
- `main.js`: 서비스워커 `controllerchange` 시 1회 `location.reload()` (새 워커가 제어권을 가져가면 새 파일로 다시 로드). 무한 새로고침 방지 플래그.
  - (보충 규칙) 주행 중(BLE connected/reconnecting)이거나 데모 중에는 재로드하지 않고, 토스트 "새 버전이 준비되었습니다 · 설정 › 앱에서 새로고침"을 1회만 띄운다. 판단은 `js/update-policy.js`의 `controllerChangeAction`(단위 테스트 `tests/update-policy.test.mjs`).
- 설정 시트 맨 아래에 현재 버전 표시: "버전 2.1.0".

### 15.2 새로고침(캐시 삭제) 버튼
- 설정 시트 "앱" 섹션(맨 아래, 버전 표시 옆): **"최신 버전으로 새로고침"**.
- 동작: 모든 서비스워커 `unregister()` → `caches.keys()` 전부 `delete` → `location.reload()`. 사용자 설정(localStorage: 비밀번호, 마지막 기기, 카메라 DB, 사운드 등)은 지우지 않는다.
- 누르면 토스트 "최신 버전을 불러옵니다" 후 실행.

### 15.3 종료 버튼
- 설정 시트 "앱" 섹션: **"종료"** (빨간 글씨).
- 동작 순서: 데모 중지 → BLE 해제(구독 해제 176[0] 송신 후 연결 종료, 기존 `ble.disconnect()`) → 자동 연결·재연결 타이머 중지 → 오디오 정지 및 `AudioContext.close()` → GPS 감시 해제 → 화면 꺼짐 방지 해제 → 전체화면 해제 → `window.close()` 시도.
- 브라우저는 사용자가 연 탭을 스크립트로 닫지 못하는 경우가 많다. 300ms 후에도 페이지가 남아 있으면 전체 화면 오버레이: "종료되었습니다. 블루투스·GPS·사운드가 모두 꺼졌습니다. 이제 탭이나 앱을 닫아도 됩니다." + **"다시 시작"** 버튼(`location.reload()`).
- 종료 상태에서는 자동 연결이 다시 시작되면 안 된다(오버레이에서 다시 시작을 누르기 전까지).

### 15.4 카메라 DB 안내 문구
- 현재 문구 `CSV: 위도,경도,제한속도 · JSON: [{"lat":37.5,...}]`는 오류처럼 보인다는 사용자 피드백. 다음으로 교체:
  - "CSV 파일: 한 줄에 위도,경도,제한속도 (예: 37.5665,126.9780,60)"
  - "JSON 파일도 불러올 수 있습니다."

### 15.5 검증
- `npm test`: 기존 + `APP_VERSION`과 sw.js 캐시 이름 일치 테스트.
- 정적 검사(스모크): sw.js에 `cache: 'no-cache'`와 `cache: 'reload'` 존재.
- 스모크(390×844, 844×390): 설정 시트에 버전·새로고침·종료 버튼이 보이고 다른 요소와 비교차. 새로고침 버튼 → 페이지가 다시 로드되고 localStorage 값(예: 사운드 설정) 유지, `caches.keys()` 결과에 이전 캐시 없음. 종료 버튼 → 오버레이 표시, 데모 중지 상태, 오디오 컨텍스트 closed, 다시 시작 → 정상 화면.
- 새 사운드 4종·테마 5종 버튼 각각 클릭 시 상태 반영 확인(예: `document.documentElement.dataset.theme`, 사운드 프로필 상태 노출 값)과 콘솔 에러 0 — 기존 검사 유지.

## 16. v2.2: 트윈 가로 정렬, 경고음 기본값, 화면 켜짐 유지

실기기(가로 전체화면, 약 1000×460 CSS px) 보고.

### 16.1 트윈 다이얼 가로 정렬
- 현상: 두 다이얼·속도·kW 묶음이 화면 오른쪽으로 치우치고 왼쪽 약 1/3이 비어 있음. 원인: 가로 레이아웃에서 좌하단 카메라 배너를 피하려고 구성 요소를 viewBox 오른쪽에 배치했기 때문(§14 리뷰 과정).
- 규칙: 게이지 구성 전체(두 다이얼, 속도 숫자, 단위, 제한속도, 방향지시등, kW)의 **가로 중심이 viewBox 가로 중심(±2%)** 에 오도록 배치한다. 카메라 배너는 오버레이이므로 피하지 않는다(배너는 일시적, 겹쳐도 됨 — 단 속도 숫자와는 비교차 유지: 필요 시 가로 모드 배너를 상단 중앙(상태줄 아래)으로 옮긴다).
- arc 가로도 같은 규칙을 확인(이미 중앙이면 변경 없음).
- 스모크: arc·twin 가로 뷰포트(844×390, 780×340, 640×360, **1000×460** 추가)에서 SVG 안 보이는 요소들의 합집합 bbox 가로 중심과 클러스터 영역 가로 중심의 차이 ≤ 클러스터 폭의 3%.

### 16.2 경고음 기본값 OFF
- 경고음(핸들 경고·카메라 경고 차임) 기본값을 OFF로. 사용자가 켜면 저장(localStorage)하고 다음 실행에도 유지. 저장값이 없으면 OFF.

### 16.3 화면 켜짐 유지
- 기존: BLE 연결 중 또는 데모 중에만 Wake Lock.
- 변경: **앱이 화면에 보이는 동안 항상** Wake Lock 요청(종료 버튼을 누른 뒤는 제외). `visibilitychange`로 다시 보일 때 재요청, 시스템이 해제하면(`release` 이벤트) 보이는 상태에서 재요청.
- 미지원 브라우저는 조용히 무시. 설정 시트 "앱" 섹션에 상태 한 줄 표시: "화면 켜짐 유지: 사용 중 / 이 브라우저는 지원하지 않음".

### 16.4 구현 중 승인 사항 (리뷰 확정)
- 가로 트윈 카메라 배너는 좌상단에 둔다(상단 중앙은 제한속도 표지와 겹침). 링에 살짝 닿는 것은 일시 오버레이라 허용.
- 화면 켜짐 상태는 "사용 중 / 대기 / 이 브라우저는 지원하지 않음" 세 가지로 표시한다("대기"는 보이지 않을 때나 요청 전).

## 18. 배기음 v3 앱 적용: V10 (v10b 프리셋)

### 18.1 방식: 미리 렌더한 RPM 루프 + 크로스페이드
- 실시간 물리 모델은 휴대폰 CPU 부담과 끊김 위험이 있어 쓰지 않는다. 게임에서 쓰는 표준 방식으로 간다: **여러 RPM에서 미리 렌더한 짧은 루프**를 현재 RPM에 맞춰 가까운 두 개를 섞고, 재생 속도(playbackRate)로 사이 음높이를 맞춘다.
- 루프 렌더(`tools/engine-render/render.mjs`에 `loops` 모드 추가):
  - 프리셋 `v10b.json`, RPM 1000부터 9000까지 500 간격 = 17개.
  - 길이: 약 1.0초에 가장 가까운 **엔진 사이클 정수배**(사이클 = 120/rpm 초)로 잘라 이음새가 맞게 하고, 원본 방식 크로스페이드로 루프를 만든다.
  - **공통 게인**: 파일별 정규화 금지. 17개 전체에서 가장 큰 피크가 -1 dBFS가 되도록 같은 배율을 적용(RPM별 자연스러운 음량 차이 유지).
  - 출력: 32 kHz, 16-bit mono WAV → `app/audio/v10/rpm-<rpm>.wav`. MP3는 앞뒤 무음 패딩 때문에 루프가 끊기므로 쓰지 않는다. 총 용량 2 MB 이하.
  - 렌더 설정(RPM 목록, 길이 규칙, 게인)은 `tools/engine-render/v10-loops.json`에 두고, 같은 명령으로 다시 만들 수 있게 README에 한 줄.
- 재생(`app/js/audio/v10.js`):
  - 17개 루프를 `fetch` → `decodeAudioData`로 미리 디코드(첫 선택 시 1회, 진행 중 토스트 "V10 사운드 불러오는 중").
  - 각 루프마다 `AudioBufferSourceNode(loop=true)` + `GainNode`. 현재 RPM r에 대해 바로 아래·위 루프 두 개만 소리 냄: 섞는 비율 t = (r − r_lo)/(r_hi − r_lo), 음량은 등전력(cos/sin) 크로스페이드. 각 루프 playbackRate = r / r_loop (최대 ±25% 범위로 제한).
  - 나머지 루프는 gain 0(정지하지 않고 계속 돌려 위상 튐 방지). 휴대폰 부담이 크면 이웃 2개 + 다음 후보 1개만 재생하도록 최적화해도 됨(보고).
  - 부하(페달) 표현: 마스터 로우패스 컷오프 = 1.2 kHz + 페달비율 × 6 kHz, 음량 = 0.45 + 0.55 × 페달비율. 회생(kW<0)·페달 0이면 컷오프 1.2 kHz, 음량 0.45. 시상수 0.08초.
  - 모든 파라미터 변경은 `setTargetAtTime`으로 부드럽게.
- 가상 변속기(`app/js/audio/rpm-model.js`, 순수 함수, 다시 만듦):
  - 7단, 공회전 950rpm, 레드라인 8800rpm, 휠 둘레 2.0m, 기어비 [3.2, 2.3, 1.75, 1.4, 1.15, 0.95, 0.8], 최종감속 3.6.
  - 업시프트 RPM = (0.45 + 0.47 × 페달비율) × 레드라인. 다운시프트: RPM < 0.35 × 레드라인이고 한 단 내려도 레드라인 × 0.9 미만이면.
  - 변속 시 RPM은 새 기어 값으로 0.12초에 걸쳐 이동, 변속 후 0.35초 재변속 금지.
  - 정차(속도 < 2km/h): 공회전 ± 20rpm 느린 흔들림. 정차 중 페달을 밟으면 공회전 레브(950 + 페달비율 × 0.6 × 레드라인, 상승 0.15초/하강 0.35초).
  - RPM 스무딩 시상수 0.08초, 출력 범위 [950, 8800].
- 미리듣기(가속 사운드 테스트) 버튼: 누르는 동안 정차 공회전 레브 경로를 그대로 사용.

### 19.3 화면 방향 전환 버튼 (휴대폰 회전 잠금 상태에서도)

- 동작: (1) 먼저 `screen.orientation.lock('landscape'|'portrait')` 시도(필요하면 전체화면 먼저 요청). 자동이면 `unlock()`. (2) lock이 실패하면(회전 잠금·미지원·전체화면 아님 등) **CSS 회전 대체**: 앱 루트(`.app`)를 90° 회전하고 너비·높이를 뷰포트 높이·너비로 바꿔 가로(또는 세로) 화면처럼 보이게 한다.
- CSS 회전에서도 레이아웃이 맞도록 **가로/세로 레이아웃 판단을 뷰포트가 아니라 앱 루트 크기 기준으로** 바꾼다: `.app`에 `container-type: size; container-name: app`을 주고, 기존 `@media (orientation: portrait|landscape)` 규칙을 `@container app (aspect-ratio < 1)` / `(aspect-ratio >= 1)`로 옮긴다(동작은 동일하게). 시트·토스트·오버레이 등 `position: fixed` 요소도 회전된 루트 안에서 올바르게 보이도록 루트 안에 두거나 같이 회전.

- 스모크: 390×844 뷰포트에서 "가로" 강제(lock 실패 경로를 강제로 타게 해서 CSS 회전) → 앱 루트 bbox가 뷰포트 안, 가로 레이아웃 규칙 적용(예: 가로용 SVG viewBox 선택), 버튼 클릭이 정상 동작(시트 열기). 844×390에서 "세로" 강제도 동일.

- arc·twin·hud(SVG): 방향지시등 크기 1.5배, 겹침·최소 크기 검사 유지.

### 19.5 사각지대 경보 표시 (화면 효과, 데이터 연결은 보류)
- 화면 효과: 좌/우 가장자리에 붉은 앰비언트 글로우(화면 높이 전체, 안쪽으로 약 18% 폭까지 투명해지는 그라디언트, `rgba(255,40,60,0.55)` → 0, 1.2초 주기로 은은하게 숨쉬듯 밝기 변화). 방향지시등이 같은 쪽으로 켜져 있으면 더 강하게(불투명도 0.85, 0.4초 주기 깜빡임)하고 경고음(경고음 설정이 ON일 때만) 1회.
- 모든 테마 위에 겹치는 오버레이(`pointer-events: none`), HUD 반전 시 함께 반전.
- 데이터: **현재 TSL 텔레메트리(176) 파싱에는 사각지대 필드가 없다.** 새 바이트를 추측해서 읽지 않는다. 상태 객체에 `blindLeft`, `blindRight`(기본 false) 자리만 만들고, 프로토콜 정보가 확인되면 파서에 연결한다.
- 데모에서는 시나리오 중 좌·우 각각 한 번씩 켜서 효과를 확인할 수 있게 한다(좌측은 좌 방향지시등과 겹치는 구간 포함).

### 19.6 공통
- 버전 2.4.0, sw 캐시 이름 동기화, 신규 파일은 셸·APP_FILES에 추가.
- 테스트: camera-logic 단위 테스트(방향 파생 15m 규칙, ±35°, 접근 판정, 방향 미정 시 무경고, 15km/h 미만 무경고, 카메라 방향 ±45°), 기존 스모크 전체 + 19.3 회전 검사 + 사각지대 오버레이가 보이고 다른 버튼 클릭을 막지 않음.

### 19.7 카메라 DB 다운로드 링크
- 설정 → 카메라 경고, "JSON/CSV 열기" 줄 아래에 링크 버튼 **"공공데이터 카메라 DB 받기"** 추가. 누르면 새 탭(`target="_blank" rel="noopener"`)으로 `https://www.data.go.kr/data/15028200/standard.do` (전국무인교통단속카메라표준데이터)를 연다.
- 링크 아래 안내 한 줄: "열린 페이지에서 JSON 다운로드 → 받은 파일을 'JSON/CSV 열기'로 불러오세요."
- 파일 직접 다운로드 주소는 공공데이터포털이 페이지 안에서 발급하므로(고정 주소 미확인) 페이지 링크로 둔다.
- 이 표준데이터 JSON(`records` 배열, `위도`·`경도`·`제한속도` 필드)은 기존 가져오기가 이미 처리한다(사용자가 44,650개 가져오기 성공). `도로노선방향`은 상·하행 구분 코드라 각도가 아니므로 19.1의 카메라 방향으로 쓰지 않는다.

### 19.8 리뷰 확정 사항
- 카메라 경고는 진행 방향(GPS 또는 위치 계산)이 미정이면 울리지 않고, 전방 ±35°와 접근 중일 때만 울린다. 첫 평가는 접근 중으로 본다.
- 25m 이내 카메라는 방위각이 불안정하므로 전방 판정을 생략하는 기존 규칙을 유지한다.
- 세로 방향지시등을 키우며 속도 숫자 칸을 화면 가장자리까지 넓히고, 글자 크기는 칸 폭에 맞춘다. 트윈 가로는 방향지시등을 출력 다이얼 아래로 옮기고 kW를 올린다.
- 방향 전환 버튼 아이콘은 자동(순환 화살표), 가로·세로(사각형)로 한다.
- 사각지대 경고음은 같은 쪽 방향지시등이 켜지는 순간에만 울린다(경고음 설정이 ON일 때).
- 실기기 CSS 회전 확인과 사각지대 비트 확인은 사용자 확인으로 넘긴다.
